# Запуск через подписку ChatGPT

Решение Альфреда от 22.10.2026: использовать подписку; для OpenWiki допустимо
штатное подключение к ChatGPT вместо Codex CLI. Платный API не используется.
Модель обеих систем: `gpt-6-luna`, `reasoning.effort=medium`.

## Что проверено живыми вызовами

- Codex CLI 0.163.0-alpha.11: вход ChatGPT и синтетический запрос с JSON Schema.
  Проверка прошла, 1 модельный вызов. Пользовательские config/rules отключены.
- OpenWiki 0.7.2, `6c14bff27830034bfd70c15bde46825d7686ec60`, штатный personal
  init: пустая Wiki, один вымышленный январский текст, 9 запросов, все HTTP 200.
- Штатный personal update: добавлен вымышленный февральский текст; обе встречи
  найдены в результирующих статьях. 16 запросов, все HTTP 200. В каждом запросе
  проверены model, medium и store=false. Проверка настоящей квоты — перед каждым.
- Tesla: неизменённый native compile на Linux, native fcntl, GPT‑6 Luna medium
  через Codex CLI 0.163.0-alpha.11. Два месяца, 4 живых вызова: пустая Wiki
  создана, следующий факт добавлен, оба найдены в статьях. Нативные проверки
  цитат и применения включены; только транспорт направлен сразу в Codex.
- Первый живой fixture Tesla остановился после двух успешных модельных ответов:
  штатная проверка отклонила статью без обязательного заголовка. Он сохранён.
  В следующем fixture проверяющий код уже фиксирует такие отказы и продолжает
  к следующему месяцу; входы, промпты, модель и core ingest не менялись.
  Этот повтор прошёл. Предыдущий отказ не удалён и не превращён в успех.
- Первый update остановлен после 12 запросов ограничителем синтетического теста.
  Сохранён как незавершённый; повтор начат с исходного январского состояния,
  предел увеличен до 24. Это изменение тестового предела, не промптов метода.
- Подготовлены 15 offline проверок; они проходят. Отдельно проверено, что
  исследовательские инструкции не меняют production canon и admin DB.
  Контрольные суммы вложенного эталона также защищены общим хешем снимка.

Синтетические прогоны не входят в исследовательскую выборку. Даже наличие двух
тестовых фактов не доказывает качество исторической Wiki.

## Ровно что изменено в OpenWiki

Оригинальная версия не знает reasoning-параметр GPT‑6 Luna. Отдельный
`openwiki-luna-compat.patch` добавляет эту модель в таблицу `openai-chatgpt` и
распространяет готовый Luna transport на её точный ID. Код personal ingestion,
промпты, инструменты и организация Wiki сохранены. Исследование должно указывать
**OpenWiki 0.7.2 + раскрытый патч совместимости**, не неизменённый upstream.
Более свежий HEAD `305599f8e44203f9ca6b74bb6b38eebaf0b0405e` проверен:
исправлений этих таблиц в нём нет, поэтому исходный закреплённый commit сохранён.

Сборка использует закреплённый pnpm-lock; отдельно установлен штатный бинарный
модуль better-sqlite3 12.11.1, который отсутствовал после install --ignore-scripts.

## Учёт и секреты

Логи и отчёты находятся в частном `storage/experiments/yunost-2024/working/`:
`subscription-cli-check-v1`, `openwiki-subscription-check-v1/v2/v3`,
`openwiki-subscription-update-v1/v2`. У v1/v2 init было 0 запросов к модели:
не был установлен SQLite-модуль. Успешные init/update — v3 и update-v2.
Отчёты, входы, выходы, CLI-логи и ledger обоих Linux fixture Tesla перенесены
в `working/tesla-subscription-checks-v1`; 54 файла защищены контрольными суммами.
Linux CLI получен из официального npm, целостность проверена по npm SHA-512.
Для Linux fixture Tesla использован временный отдельный CODEX_HOME с текущим
входом подписки. После завершения весь временный каталог авторизации удалён;
рабочий вход пользователя не изменён.

OpenWiki получает существующую авторизацию Codex только в память процесса.
Заголовки запросов не сохраняются. Проверка успешного update просмотрела файлы
его home на отсутствие access/refresh/id tokens. Разрешён только endpoint
ChatGPT Codex; платные провайдеры и неизвестная квота останавливают тест.
Если осталось ≤10% любого окна, новый вызов запрещён. Сброс квоты не расходуется.

Рабочий эталон `working/user-reviewed-reference-v2` содержит 197 утверждений:
178 основных и 19 дополнительных. Список в целом принят Альфредом; одна явная
поправка: «В февральской публикации Альфред назван командиром „Юности“».
Цитаты и версия 1 сохранены. Это ИИ-черновик с общей проверкой пользователя,
не независимая двойная разметка. Эталон не передавался генераторам.

## Что ещё отделяет проверки от полного эксперимента

Нужны одинаковая изолированная Linux-среда для двух систем, проверенный порядок всех месячных
обновлений с сохранением контрольных точек и обработкой остановки по квоте.
Windows не используется как основной runner: ранее найдено расхождение CRLF/LF
в штатных проверках хешей Tesla. В подготовке используется отдельная Linux-копия.

Оплаченных API-вызовов нет. Исторические Wiki ещё не построены, оценок качества
и победителя нет. Рабочая Wiki, её ledger, production canon и сайт не меняются.

## Последняя проверка подготовки

Для общего Linux runner установлены Node 22.22.1, pnpm 11.25.0 и production
зависимости по тому же pnpm-lock. Compiled dist скопирован из проверенной сборки;
два изменённых исходника соответствуют раскрытому патчу (переносы CRLF → LF
нормализованы для его применения). Штатный better-sqlite3 установлен отдельно.
Первый Linux init завершился до модельных запросов (0); общее окружение пока
не объявляется проверенным. Последующая проверка квоты показала остаток 3%
короткого окна. Новые модельные вызовы запрещены правилом AGENTS.md (≤10%).

Перед историческим запуском обнаружено и исправлено: месячные задания OpenWiki
брали original canon, хотя общие файлы и промпты Tesla уже использовали research
copy. Теперь фабрика задания получает ту же выбранную папку канона; добавлена
проверка этого пути. Снимки e17102c0c15db7666790 и 2770fb8cf2e24559ed2a
оставлены в истории подготовки и не подходят для запуска. Реальным генераторам
они не передавались. Текущий исправленный снимок указан в частном CURRENT.json.

Тонкие адаптеры одного месяца готовы: tesla_run_month.py и study-режим
openwiki_subscription_check.mjs. Они проверяют хеши входов и предыдущий месяц,
сохраняют результаты в новом каталоге, не выставляют оценки качества сами.
Их живое выполнение по корпусу и координация всех повторов ещё не проверены.

## Изоляция и запуск одного месяца (редакция 4)

`study_run.py` берёт следующий шаг строго из зафиксированного allocation.json.
Он проверяет весь snapshot, передаёт в Linux только текущий месяц и завершённый
checkpoint той же системы и того же повтора. Разметка и будущие месяцы остаются
снаружи. В синтетических проверках исторические тексты вообще не передаются.

Граница чтения обеспечивается готовым `bwrap`, а не только read-only режимом
Codex. `job_sandbox.py` создаёт отдельный корень файловой системы с публичным
runtime, одним входом и одним новым выходом. Предыдущий checkpoint доступен
только для чтения. Чистый CODEX_HOME содержит только временную авторизацию;
shim выключает пользовательские config/rules и web search в native Codex exec.
Вложенный bwrap самого Codex скрывает даже архив и распакованный source Tesla:
процесс получает только stdin задания, read-only JSON Schema и новый выход.
Его файловая граница проверяется тем же mount builder без вызова модели.
Native compiler, алгоритмы ingest и рабочие промпты этим не меняются.

`runtime-lock.json` фиксирует Codex binary, версии Node/Codex, lockfile,
дерево 352 compiled-файлов OpenWiki и два исходника раскрытого патча.
Перед каждым worker выполняются офлайн-проверки runtime и недоступности
посторонних исследовательских папок; при отказе запуск вне изоляции запрещён.

Каждая попытка сохраняет внешний launcher report, включая отказ до создания
worker report. OpenWiki регистрирует сетевую попытку до отправки; потеря SSE
не может завершиться успешным статусом. Результат и полный список его файлов
замораживаются хешами. В экспорт не включается распакованный native source:
он восстанавливается из сохранённого Git-архива и его SHA.

После неуспешного шага расписание останавливается. Автоматических повторов,
подмены результата более удачной попыткой и исключения отказов из отчёта нет.
Решение о восстановлении после инфраструктурной остановки записывается отдельно
до продолжения. Предварительный проход разрешит историческую генерацию только
после сохранённых синтетических проверок обеих систем в этом же frozen runtime.
