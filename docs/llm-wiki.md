# Летопись: текущая архитектура и компиляция

## Ответы

Оба чата используют `backend/wiki/service.py`: поиск по Markdown → чтение нужных разделов → ответ с первоисточниками. Ответ без прочитанной страницы и известной ссылки не принимается. При отсутствии подтверждений возвращается «В архивах нет данных.». Ошибка LLM возвращает HTTP 503. Neo4j, Qdrant и эмбеддинги в этом пути не используются.

`GET /api/v1/wiki/page` отдаёт статью целиком. Инструмент модели `wiki_read` читает до 6000 символов и возвращает `truncated` и `next_offset` для продолжения. Приватные каталоги, редакторские заметки и страницы со статусом `stub` исключены из публичного каталога и поиска.

Исходные `schema/rules.md` и `schema/rules_mapping.md` включаются в инструкции дословно. Канон не редактируется; трактовки меняются только в mapping.

## Провайдеры компиляции

По указанию Альфреда от 05.10.2026 основной поставщик — бесплатные модели OpenCode CLI. Доступность и нулевая цена проверяются по текущему каталогу CLI. Следующий поставщик — GPT-6 Luna через Codex CLI: Low для извлечения, Medium для обновления статьи. Sol Medium используется для сложных редакторских решений по необходимости.

Перед вызовом Codex runner читает `account/rateLimits/read` из официального app-server. При остатке 10% или меньше в любом окне новые вызовы Codex не выполняются. Если прочитать лимиты нельзя, процент не угадывается. OpenCode может не раскрывать оставшуюся квоту; ошибки лимита фиксируются как наблюдаемая недоступность, а не выдуманный процент.

## Стадии

1. Инвентаризация разрешённых JSONL, архивных выдержек и метаданных групп. Ключ источника — канонический wall-ID либо типизированный `archive:`/`group:` ID плюс хэш полного исходного текста. Разные версии сохраняются отдельно. Изменение размера батча не теряет идентичность поста. Архивные выдержки сверяются с указанными строками исходного файла; даты снимка метаданных и периоды должностей не угадываются.
2. Извлечение структурированных фактов из ограниченного батча. Проверяются ID, хэш, дословная цитата, даты, уровень должности и атрибуция. Сомнения, розыгрыши и отказы сохраняются для проверки.
3. Обновление конкретных статей с контекстом из 1–5 файлов. Модель выбирает статью и предлагает точечные замены или добавления; программа собирает результат из исходного текста и этих правок. Старые подтверждённые факты и источники сохраняются; дубли проверяются по существующему тексту. Новая статья требует полного frontmatter и разрешимых ссылок.
4. Предложение сохраняется отдельно, проверяется исходный хэш статьи, затем текст записывается атомарно. Прогресс отмечается после записи. Повторный запуск восстанавливается по сохранённым входам и выходам.
5. Редакторская проверка противоречий. Отсутствие подтверждения не превращается в установленный факт. `extracted` и `applied` не означают завершённую проверку всей вики.

`storage/wiki/_ingest/ledger.sqlite` хранит прогресс. Одновременно ledger может использовать только один compiler. При восстановлении сначала применяются уже извлечённые факты; сохранённое предложение переиспользуется только с тем же контекстом статьи и промптом. `storage/wiki/_review/` хранит редакторские вопросы. Оба каталога приватные. Перед массовой компиляцией сохраняется резервная копия в `storage/backups/`.

## Локальные команды

```bash
# Справка по pipeline и его действующим параметрам
.venv/bin/python scripts/wiki_ingest.py --help
.venv/bin/python scripts/wiki_ingest.py compile --help

# Полные статьи и подписи первоисточников на сайте
.venv/bin/python -m scripts.wiki_sources

# Проверки без живых LLM и графовых сервисов
LANGFUSE_ENABLED=0 .venv/bin/python -m unittest backend.wiki.test_runtime backend.wiki.test_api_runtime backend.wiki.test_ingest backend.wiki.test_archive backend.wiki.test_legacy_progress -v

# Frontend: только Docker
sudo -n docker run --rm -v "$PWD/frontend:/app" -v graphrag_npm_cache:/root/.npm -w /app node:20-alpine sh -c "npm ci && npm run build && npm test -- --run"
```

В разрешённых 19 корпусах на момент инвентаризации — 9397 строк и 9236 разных канонических wall-ID. Это объём очереди источников, не число уже обработанных постов. `posts_kgeu_official.jsonl` и `posts_spoyunost.jsonl` исключены каноном.

Прежняя обработка учитывается отдельно: `reconcile-legacy` переносит только посты из пакетов, отмеченных и в `_batches/done.txt`, и в `log.md`, с совпадающими текстом и датой. Состояние `legacy_processed` означает документированную прежнюю обработку, а не повторную проверку полноты фактов. Ссылки в статьях сами по себе не доказывают завершённую обработку поста. На 05.10.2026 перенесено 1765 источников из 124 завершённых пакетов; ещё 40 учтены новым pipeline, 7525 остаются в очереди. Расхождения сохранены в приватном `legacy-reconcile-report.json`. Статьи при переносе не изменяются.

В очередь также включены 76 архивных выдержек, не совпавших с JSONL по дате и нормализованному тексту, и 18 карточек сообществ. Несовпадение не доказывает новизну факта: повторы проверяются при компиляции. Всего в основной очереди 9330 источников; обработка началась отдельными пакетами. Точный текущий прогресс показывает команда status; число источников не означает число готовых статей.

Пробный прогон выявил и исправил принятие вложенного объекта из неполного JSON. Codex получает строгую JSON Schema; неполные ответы не считаются готовыми результатами. Предложения, удаляющие существенную часть существующей статьи, её ссылки или подтверждённые строки, отправляются на проверку. Существующие статьи могут иметь старые метаданные либо заголовок без frontmatter; полный набор метаданных обязателен для новых статей.

## Codebase Memory

Проектная копия skill лежит в `.opencode/skills/codebase-memory-mcp/`. Это публичная версия из GitHub awesome-copilot; точный Windows-файл ещё не сравнен с ней. MCP помогает изучать код. Данные `storage/` игнорируются кодовым индексом и извлекаются собственным pipeline Wiki. Создание индекса требует отдельного согласия согласно skill.

## Публикация

Код коммитится и сразу отправляется в SSH `upstream`, ветку `gid-web`. Секреты и контент `storage/` не публикуются в Git. Синк и подключение к Кириллу отменены Альфредом. Новый сервер будет выбран после готовности Wiki.

Массовая обработка всей очереди запущена после пробного пакета. Состояние процесса — `storage/wiki/_ingest/runs/main-2026-10-05/continuation-state.json`; журнал — `continuation.log`. Успешный проход очереди не означает, что все редакторские вопросы закрыты.

### Постоянная сборка на Джоле

`scripts/wiki_compile_worker.py` продолжает ту же очередь пакетами до 10 источников и 16000 символов в период 08:00–23:00 по Москве. Шаблон пользовательской службы — `deploy/systemd/tesla-wiki-compile.service`. Для запуска после загрузки компьютера пользовательскому менеджеру systemd нужен `loginctl enable-linger jolf`; служба включается через `systemctl --user enable --now tesla-wiki-compile.service`. Ночной сон компьютера приостанавливает процесс, пробуждение позволяет ему продолжиться; после перезагрузки процесс восстанавливается по ledger. Расписание сна компьютера служба не меняет.

OpenCode вызывается первым. Шаблон разрешает резервную Luna Low/Medium после отказа бесплатных моделей; перед каждым таким вызовом существующий guard читает настоящие квоты обоих окон и требует остаток строго больше 10%. При недоступных квотах Luna не вызывается. Сам worker без `--codex-fallback` использует только бесплатные модели.

При отказе поставщиков выполняются повторные попытки через 15, 30, затем 60 минут. Время следующей попытки сохраняется и учитывается после перезапуска. Процент оставшейся квоты бесплатного OpenCode не выдумывается: процесс реагирует на реальные ошибки. Повреждённые результаты и ошибки проверки данных останавливают автоматическую обработку со статусом `needs_review`; успешное исчерпание автоматической очереди отмечается как `automatic_queue_finished`, но редакторские вопросы остаются. Отдельные блокировки не допускают двух workers или двух компиляторов для одного ledger.

Полнота ответа извлечения проверяется до признания вызова успешным: один результат на каждый переданный ID и хэш, без пропусков и повторов. Неполный ответ сохраняется в `rejected/` и допускает попытку следующего поставщика; недействительный старый кэш также сохраняется отдельно и запрашивается заново. Если все поставщики не вернули полный результат, worker выдерживает паузу, сохраняя источники в очереди. Пропущенные результаты не выдумываются и не считаются обработанными.

## Проверка ускорения

Основная очередь запускалась с пакетами до 25 источников и лимитом 32000 символов исходного текста. Один из запросов MiMo исчерпал 32000 токенов ответа почти исключительно рассуждениями и не вернул JSON; резервная модель повторно обрабатывала тот же пакет. Это расход времени, а не только размер источников.

Для LongCat исправлена передача Low/Medium через `--variant`: её текущий официальный каталог поддерживает эти режимы, а MiMo и Nemotron не объявляют вариантов. Увеличение пакета до 50 проверяется отдельно, без записи в основную Wiki. Извлечение и обновление статьи остаются отдельными стадиями; полнота каждого пакета и источники фактов проверяются.

Основной бесплатный поставщик переключён на LongCat с Low для извлечения и Medium для статьи: большие запросы MiMo уже завершались исчерпанием бюджета рассуждений без готового JSON, затем выполнялась повторная обработка. Повторяющиеся модели в списке резервных попыток пропускаются. MiMo и Nemotron сохранены как резерв; квота Codex по-прежнему проверяется перед каждым резервным вызовом.

Проверка большого пакета с одним лишь `--variant low` завершилась без JSON: 46 источников, 619 секунд, 31999 токенов рассуждений в последнем шаге. Увеличение батча пока не принято. Оба поставщика MiMo и LongCat документируют `thinking.type=disabled`; для механического извлечения и проверяемых текстовых правок этот параметр теперь передаётся через настройки модели. Luna сохраняет Low/Medium; сложные противоречия остаются для редакторского разбора.

Живая проверка LongCat без глубоких рассуждений: 10 источников за 104 секунды, 6 с извлечёнными фактами, 3 на проверку, 1 без полезных сведений; 0 токенов рассуждений. Обновление одной статьи Сириуса в отдельной копии — 27 секунд, предложение прошло проверки и применилось. Это замеры небольшого пакета и одной статьи, а не доказательство скорости всей очереди. Основной запуск продолжает работу с пакетами до 10 источников и 16000 символов, с прежними проверками цитат, дат и сохранения статей.

В текущем каталоге обнаружены и проверены как бесплатные Muse Spark 1.3 и Ling 3.1 Flash; они добавлены как явно выбираемые альтернативы. Старая успешная сессия использовала Muse Spark, однако новые пробные вызовы Muse Spark и Ling вернули ошибки поставщика. Повторять недоступные модели на каждом пакете не требуется; основной вариант — успешно проверенная LongCat.
