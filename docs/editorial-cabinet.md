# Редакционная и кабинет «Теслы»

Кабинет работает с одной Wiki Штаба «Тесла». `/editorial` предназначена для
ручной редактуры, `/admin` — для документов, VK-источников и задач сбора.
Обе страницы используют существующий вход администратора и фиолетовый стиль.
Проекты, графы, ключи и отдельная передача дел отсутствуют в рабочем меню.

## Работа со статьёй

1. Выбрать статью и открыть редактор. Можно создать новую статью-черновик.
2. Проверить источники рядом с текстом, внести изменения и сохранить черновик.
   Черновик не изменяет опубликованный Markdown и не участвует в ответах Wiki.
3. Посмотреть результат, указать причину изменения и явно опубликовать.
4. В истории доступны предыдущие публикации и импортированные архивные снимки.
   Восстановление создаёт новую запись, сохраняя промежуточные версии.

Изменения сравниваются с версией, открытой редактором. При конфликте API
возвращает 409; интерфейс сохраняет локальный текст и предлагает сравнить его
с текущим. Новые ссылки `[[...]]` должны вести на существующие статьи.
Перед публикацией сохраняется исходная версия; замена файла атомарная.
При сбое записи сохранённая попытка видна в частной истории как неопубликованная.
Её можно открыть и явно опубликовать повторно; текущая статья при сбое сохраняется.
При ручном редактировании файлов вне кабинета изменения также попадут в
историю при следующем чтении. Такие внешние редакторы не используют блокировку
кабинета: одновременно редактировать один файл снаружи и через API не следует.

## Дискуссии

В одной очереди находятся редакторские замечания, расхождения источников и
явные вопросы хранителю. Есть связь со статьёй, ответственный, комментарии,
решение и состояния «Ждёт редактора», «Ждёт хранителя», «Решено».
Закрытие требует записанного основания. Старые записи `issues.json` импортируются
однократно по идентификатору с сохранением исходной записи; неопределённость не
превращается автоматически в вопрос хранителю. Дискуссии остаются частными.

## Источники и документы

Кабинет принимает PDF, DOCX, TXT, JSON и Markdown размером до 25 МБ.
Извлечение текста — отдельный явный шаг; текст сохраняется целиком, с хешами
оригинала и результата. Дата загрузки не становится датой публикации документа.
Сканированный PDF без текстового слоя требует отдельного OCR; кабинет сообщает,
если текст извлечь не удалось.

Входящий материал можно просмотреть и отметить рассмотренным или отклонённым.
Документ сам по себе остаётся частным. Для ссылки в публичной статье редактор
явно публикует выбранный диапазон строк. Публикуется только этот фрагмент с
устойчивой ссылкой, названием и происхождением. Он становится доступен через
существующий просмотр первоисточников Wiki.

## VK и расписание

Источники VK добавляются по HTTPS-ссылке. Сбор получает публикации в корпус
источников и во входящие материалы. Повторные попытки сохраняют историю задач;
дубли учитываются по идентификатору и хешу текста. Состояния задачи различают
очередь, выполнение, успех, ошибку и прерывание.

Отдельную публикацию можно добавить ссылкой `wall<owner>_<post>`: кабинет
ставит задачу получения одного поста через `wall.getById`. Это самостоятельный
источник, который не включается в ежедневный обход групп. Уже настроенные группы
импортируются из локального `group_links.txt` без обращений к VK и запуска задач;
комментарии и исключённые источники учитываются. При внедрении импортировано
18 групп, расписание оставлено выключенным.

Расписание ежедневного сбора использует `Europe/Moscow`, по умолчанию выключено.
Оно работает в отдельном потоке жизненного цикла API, хранит состояние в SQLite,
защищено блокировкой одного владельца и после перезапуска отмечает незавершённые
задачи прерванными. При включённом расписании очередная проверка после
пробуждения/старта выполняется по сохранённому состоянию; накопившиеся публикации
получаются с последней сохранённой отметки. Перезапуск не стирает историю ошибок.

**Сбор источников не вызывает LLM и не публикует статьи.** Массовая компиляция
`tesla-wiki-compile.service` остановлена и отключена по указанию Альфреда.
Кабинет не включает её. Управление расписанием сбора не отменяет эту паузу.

## Инструкции моделей

Редактор показывает редактируемую часть, полный действующий промпт, исходный
файл/переопределение, неизменяемый канон и историю версий. Query, extract и merge
используют общий реестр; сохранённые правки действительно доходят до CLI.
`schema/rules.md` и `schema/rules_mapping.md` добавляются дословно. Для extract и
merge добавляется редакторский skill. Версия промпта участвует в идентичности
кеша извлечения и обновления, чтобы старая инструкция не подменяла новую.
Проба чата делает настоящий запрос только после нажатия пользователем.

## Хранение и доступ

- Статьи: `storage/wiki/**/*.md`.
- Черновики, версии и дискуссии: `storage/wiki/_editorial/editorial.sqlite`.
- Входящие материалы, источники, задачи и расписание: `storage/admin_operations.db`.
- Инструкции и их версии: `storage/admin.db`.
- Опубликованные фрагменты первоисточников: `storage/wiki/_source_records.json`.
- Сессии: `storage/sessions.db`; гостевой вход даёт только роль читателя.

Старый отладочный `TESLA_ALL_ADMIN` больше не повышает гостевые права. При
миграции старые сессии, выданные в таком режиме, становятся читательскими;
для редактуры требуется новый вход администратора. Версии и комментарии
содержат серверную метку автора, а не имя, переданное клиентом.

Контент, базы и резервные копии остаются вне Git. Код публикуется в SSH upstream;
синхронизация к Кириллу отменена. Перед внедрением кабинета создан дополнительный
снимок `storage/backups/cabinet-before-2026-10-17-160835/`.
В историю добавлена 721 версия из двух существующих архивов; исходные Markdown
сохранены без изменений. Прежние редакторские замечания перенесены в дискуссии.

## Проверки

Проверки редактора используют временную Wiki: сохранность опубликованного текста
при сохранении черновика, публикация/восстановление, устаревшие версии, отказ записи,
восстановление после прерывания, история объединённых адресов, защита частных путей,
дискуссии, права доступа и публикация только выбранного фрагмента документа.
Проверки источников используют временные документы и подставной VK-клиент.
Фронтенд собирается и проверяется через Docker; Node на хост не устанавливается.
